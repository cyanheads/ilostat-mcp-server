# 0.3.0 — 2026-10-29

## Added

- **`ilostat-guide` skill** published as the `skill://ilostat-guide/SKILL.md` resource (with the `skill://{+path}` template) through `createApp({ skills: 'skills' })`; the server instructions point to it and list the `AGE_5YRBANDS_*` and `ECO_*` classification versions that overlap.
- **`ilostat_search_indicators` sex words** ([#23](https://github.com/cyanheads/ilostat-mcp-server/issues/23)). `female`, `male`, `women`, `men`, and their plurals match every indicator broken down by sex, and the notice names the filter: `sex: ["SEX_F"]` or `["SEX_M"]` for `ilostat_query_indicator`.

## Changed

- **Breaking: `ilostat_dataframe_query`** fails an unqualified read of a staged column named `current_schema` (`SELECT current_schema FROM <df>`, quoted or in any case, also in a CTE or a `query()` body) as `denied_function`, with the framework's hint to qualify it (`<table>.current_schema`). Qualified reads work.
- **`ilostat_dataframe_query`** fails an unknown `df_` name inside a `query()` body as `missing_table` naming it, where a read opening with a comment or `(` failed `invalid_sql` ([#25](https://github.com/cyanheads/ilostat-mcp-server/issues/25)).
- **`ilostat_search_indicators`** matches more derived forms through the stem fallback, so `disabled` finds `disability` and `comparable` and `secure` find their nouns ([#27](https://github.com/cyanheads/ilostat-mcp-server/issues/27)).
- **`.mcpb` bundle** sets `CANVAS_PROVIDER_TYPE=none` in `manifest.json`: the bundle has no DuckDB binding, so the three dataframe tools, which always failed `canvas_unavailable` there, are no longer listed.
- **Framework** `@cyanheads/mcp-ts-core` ^0.13.18 adopted (MCP SDK 2.4.0 through it); framework skills, scripts, `bunfig.toml`, `.mcpbignore`, root `plugin.json` and `mcp.json`, and the bug-report form are re-synced.

## Fixed

- **`ilostat_dataframe_query` provenance** ([#25](https://github.com/cyanheads/ilostat-mcp-server/issues/25)). A `register_as` result over `query('<sql>')` records `derived_from` and the parent's `datasets` (`unit_multiplier` included) as a direct `FROM <df>` does; the literal is read as DuckDB unescapes it, nested down to the gate's limit of 4.
