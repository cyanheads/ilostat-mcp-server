# 0.4.0 — 2026-11-15

## Added

- **`ilostat_query_indicator` paging** ([#33](https://github.com/cyanheads/ilostat-mcp-server/issues/33)). `limit` (default 50; a value above 5,000 is applied as 5,000, and the notice names both), `offset`, and `next_offset` reach every row of a result, up to `ILOSTAT_MAX_ROWS`, with dataframes off.
- **`ilostat_compare_geographies` paging** ([#31](https://github.com/cyanheads/ilostat-mcp-server/issues/31)). `limit` (default 50), `offset`, and `next_offset` page the areas in the `sort` order; ranks, `missing`, and `comparability` cover every area on every page.
- **`summary.areas_without_rows`** on `ilostat_query_indicator` ([#32](https://github.com/cyanheads/ilostat-mcp-server/issues/32)). Names each requested area that returned no rows, per dataset, as `not_covered` (outside the dataset's area list) or `no_rows`; `[]` when every requested area returned rows, absent when the read is incomplete, no area was named, or the result has no rows.
- **`ilostat_search_indicators` age words** ([#26](https://github.com/cyanheads/ilostat-mcp-server/issues/26)). `youth` and `young` (the 15-24 band) and `adult` (25+), or their plurals, match every indicator broken down by age, so `youth unemployment` returns `UNE_DEAP_SEX_AGE_RT` among 120 hits instead of 44; the notice says where the band's `AGE_*` codes come from.

## Changed

- **Breaking: `ilostat_dataframe_query`** refuses SQL with reason `system_catalog_access` when it uses any of these 35 names as a column alias, a table alias, or a CTE name, quoted or not, in any case: `duckdb_columns`, `duckdb_constraints`, `duckdb_databases`, `duckdb_indexes`, `duckdb_logs`, `duckdb_schemas`, `duckdb_tables`, `duckdb_types`, `duckdb_views`, `pragma_database_list`, `sqlite_schema`, `sqlite_temp_master`, `sqlite_temp_schema`, `pg_am`, `pg_attrdef`, `pg_attribute`, `pg_class`, `pg_collation`, `pg_constraint`, `pg_database`, `pg_depend`, `pg_description`, `pg_enum`, `pg_index`, `pg_indexes`, `pg_namespace`, `pg_prepared_statements`, `pg_proc`, `pg_sequence`, `pg_sequences`, `pg_settings`, `pg_tables`, `pg_tablespace`, `pg_type`, `pg_views`. 0.3.0 answered those statements with correct rows. The refusal comes from the SQL gate of `@cyanheads/mcp-ts-core` ^0.13.22, which this server runs with system catalogs denied; rename the alias or CTE (`sqlite_master` was already refused and is unchanged).
- **`ilostat_query_indicator` and `ilostat_compare_geographies` output fields** describe the page: `cap` is the `limit` applied (it was a character budget), and `truncated` is true when rows remain past the page. On query, `row_count` counts the rows read and `summary.complete` is true when the read reached the end of the result.
- **Staging with dataframes on** ([#33](https://github.com/cyanheads/ilostat-mcp-server/issues/33)). A first page whose full result passes `ILOSTAT_MAX_ROWS` returns its page unstaged with a notice that says how to reach the rest, where it failed `result_too_large`; only a page that needs rows past the ceiling fails `result_too_large`.
- **`ILOSTAT_PREVIEW_CHARS`** is the staging trigger: a first page whose result passes it is staged as a dataframe, and pages are bounded by `limit`. `ILOSTAT_MAX_ROWS` bounds the rows read as well as the rows staged.
- **A page of a result over 5,000 rows re-reads the request from its start upstream.** For a large result, SQL over the staged dataframe (dataframes on) or a narrower request is the cheap path.
- **`ilostat_dataframe_query`** fails a `PIVOT` without `IN` as `non_select_statement` (was `multi_statement`), admits the `range()` and `generate_series()` table functions with constant arguments (they failed `plan_operator_not_allowed`), and returns the binder's detail for a read that fails to prepare.
- **Overlapping age classification versions**: the server instructions, the `ilostat_dataframe_query` description, and the `ilostat-guide` skill also list `AGE_YTHBANDS_*` and `AGE_CLDVERSION_*` ([#26](https://github.com/cyanheads/ilostat-mcp-server/issues/26)). The skill also covers the age search words and paging with `next_offset`.
- **`serverInfo`** carries a `description` on `initialize`, read from `package.json` through `@cyanheads/mcp-ts-core` ^0.13.21.
- **Framework** `@cyanheads/mcp-ts-core` ^0.13.22 adopted for `DataCanvas.acquireShared` and the new SQL gate; framework skills, scripts, and `changelog/template.md` are re-synced, and `.env.example` documents `MCP_JWT_EXPECTED_AUDIENCE` and `MCP_JWT_EXPECTED_ISSUER`.

## Fixed

- **Units** ([#30](https://github.com/cyanheads/ilostat-mcp-server/issues/30)). Read from the catalog's table of contents instead of an SDMX probe, so describe, query, and compare keep `unit` and staged rows keep `unit_multiplier` while SDMX is unreachable; without the structure, `type_label` is absent.
- **`ilostat_get_country_profile` modelled values** ([#29](https://github.com/cyanheads/ilostat-mcp-server/issues/29)) read from five years before the modelled cutoff through it (`timefrom` and `timeto`), so a sex slice that ends before the indicator's latest year, such as working poverty by sex, is kept.
- **Shared dataframe canvas** ([#34](https://github.com/cyanheads/ilostat-mcp-server/issues/34)) resolves through `DataCanvas.acquireShared`: concurrent calls land on one canvas, and a cancelled call no longer fails the others.
- **Failed SDMX structure lookup** ([#36](https://github.com/cyanheads/ilostat-mcp-server/issues/36)) is remembered for 60 seconds per indicator, so calls during an SDMX outage degrade at once.
- **`latest_only` fallback** to the latest period per area and dataset, and compare's fallback from the years between to the two periods, are remembered per request for `ILOSTAT_CACHE_TTL_SECONDS`, so later pages skip the failed first read.
- **A call cancelled while its result is being staged** no longer leaves the staged table behind.
- **Unit type with no label** renders `type RT`, not `type RT (RT)`.
- **A database label that already ends with its code** is not repeated (`Labour Force Statistics (LFS)`, not `… (LFS) (LFS)`) in describe, query, compare, and search hits and facets.
- **`canvas_unavailable` recovery** on the three dataframe tools points to paging query and compare inline with `next_offset`.
- **Tool descriptions and docs** say "staging threshold" where they said "inline preview".
